## 1. О проекте

**Tsugi** (次 — «следующий», «дальше») — веб-приложение для отслеживания аниме: каталог, поиск и **расписание выхода серий**. В первой версии (MVP) поиск только по строке, без фильтров, а личного списка нет — он вырезан до следующей итерации (решено 18.09.2026).

Название отвечает на главный вопрос продукта — что следующее и когда. Прежнее рабочее название — OtakuList.

**Цель проекта:** пет-проект для портфолио. Отсюда следует, что приоритет — не количество фич, а качество исполнения: законченность, читаемый код, типобезопасность, обработка краевых случаев и внятная документация. Лучше пять доведённых до конца экранов, чем пятнадцать наполовину.

**Ключевая фича, отличающая проект от типового каталога:** расписание выхода серий с привязкой к личному списку. Каталог открывают один раз, расписание — каждую неделю.

### Решение по API

**Jikan отменён, выбран AniList GraphQL.** Обоснование (в README вынести отдельным разделом):

- запрос ровно нужных полей, без оверфетча;
- есть `bannerImage` и `coverImage.color` — баннер идёт в блок популярного, цвет обложки в подложки карточек (см. 5.1);
- есть `airingSchedule` — без него ключевая фича невозможна;
- мягче лимиты (у Jikan 3 req/sec, 60/min — поиск с дебаунсом упирается);
- есть OAuth и мутации — задел на синхронизацию личного списка.

Минус: нет русских названий (у Jikan тоже нет). Принимаем.

**Приложение обращается к двум внешним адресам** (замерено 16.08.2026 на экране расписания):

| Хост                 | Что               | Запросов на экран |
| -------------------- | ----------------- | ----------------- |
| `graphql.anilist.co` | API               | 3                 |
| `s4.anilist.co`      | обложки и баннеры | 122               |

Больше внешних обращений нет — `@vicons` и шрифты бандлятся в сборку.

Обрати внимание на пропорцию: почти весь сетевой трафик экрана — это изображения, а не данные. Это главный рычаг, если понадобится ускорить загрузку.

### Решение по типам

Типы GraphQL-ответов **не пишутся руками**. Подключается `@graphql-codegen` со схемой AniList; типы генерируются в `src/api/generated/`. Причина: рукописные типы неизбежно расходятся с запросами, и компилятор об этом не узнает.

## 3. Палитра и айдентика

![Палитра Tsugi](palette.svg)

### Токены

Значения живут в одном месте — `src/styles/theme.scss`, по блоку на тему (`:root` и `:root[data-theme='dark']`); картинка выше собрана из него. Здесь — только роли и правила, которые по значениям не видны.

- **Текст — три ступени:** `--text-strong` (заголовки), `--text` (основной), `--text-muted` (подписи, метаданные, время эфира). Нейтральные слегка тёплые, с розовой подмешкой — молочно-серые, а не стальные.
- **Акцент — заливка и текст раздельно:** `--accent` (с `-hover`, `-pressed`) — для заливок; для текста и ссылок отдельный `--accent-text`, потому что `--accent` как текст на тёмном фоне не дотягивает до нормы контраста. `--accent-text-strong` — акцентный текст с весом (число сегодняшнего дня); `-strong` значит «контрастнее», а не «темнее»: в тёмной теме он светлее.
- **Цвет текста на заливке диктует заливка:** `--on-accent` белый в обеих темах (фиолетовый тёмный при любой светлоте), `--on-success` меняется по темам (зелёный тёмный в светлой и светлый в тёмной).
- **Фиолетовый в тёмной теме светлее** (28.08.2026): Naive кладёт на заливки кнопок в тёмной теме чёрный текст, и прежний оттенок не давал нормы. Тон тот же, 258°.
- **Шкала оценки — свои токены** `--score-{high,mid,low}` с `--on-score-*` (10.09.2026): ступень шкалы — не состояние, низкая оценка не ошибка. Значения одинаковы в обеих темах — алиас на `--success` в тёмной теме ронял бы контраст текста на плашке. Середина серая, а не жёлтая: жёлтый с таким контрастом выглядит коричневым. Пороги — от 65 высокая, от 50 средняя (шкала AniList 0–100).
- **Статусы тайтла** — `--status-{cancelled,finished,releasing,planned,paused}-{background,border,text}`, применяются миксином `status-colors` в `StatusTag`.
- Ещё: `--bg`, `--surface`, `--border`, `--accent-bg`, `--success`, `--error`, `--skeleton-bg` — по названию.

Все пары проверены на контраст: текст не ниже 4.5, заливка со своим `--on-*` не ниже 4.5. Приглушать текст альфой (`color-mix(... transparent)`) нельзя: альфа подмешивает фон и роняет контраст — для этого заведены отдельные токены. Направление hover и pressed выбирается по читаемости, а не одним правилом для всех.

### Правило акцентов

- **Фиолетовый — действие и навигация:** кнопки, ссылки, активный пункт меню, выбранный день.
- **Зелёный — случившееся:** эпизод вышел, полоса ближайшей серии, подтверждение.

Одно про то, что можно сделать, другое про то, что уже произошло, — так они не спорят за внимание.

**Счётчик релизов зелёным — сознательное исключение:** счётчик про релизы, а зелёный — цвет релизного состояния. Цена — зелёный становится самым частым цветом; если начнёт спорить с полосами «вышло», счётчику стать нейтральным.

**Розовый (`--airing`, `--on-airing`) без работы:** задумывался как «в эфире», но роли разобрали фиолетовый и зелёный. Если применения не найдётся, удалить — неиспользуемый цвет рано или поздно применят наугад.

### Почему CSS-переменные, а не SCSS

Переменные Sass подставляются при сборке, в готовом CSS их нет — тему в рантайме на них не переключить. Поэтому цвета — только CSS-переменные в `theme.scss`, а компоненты знают лишь роли: `var(--surface)`, `var(--accent-text)`. Какой это цвет в текущей теме, решает тема, а не компонент. SCSS-переменные остаются для размеров и отступов (`$base-gap`, `$header-height`).

### Стыковка с Naive UI

У Naive своя тема с зелёным `primaryColor` по умолчанию. `n-config-provider` в `App.vue` получает `theme-overrides` — `LIGHT_THEME` и `DARK_THEME` из `constants/themeVariables.ts`; значения цветов — только там. Грабли:

- **`primaryColorSuppl` обязателен** — им Naive заливает плотные элементы (кнопки, переключатели), без него часть останется зелёной;
- **приглушённый текст — `textColor3`**, а не `textColorBase`;
- **покомпонентные правки** — ключи с именами компонентов рядом с `common` (сейчас `Tag`).

### Айдентика

- **Логотип «Tsugi»** — шрифт Dangrek (Google Fonts, SIL OFL), переведён в кривые, чтобы не зависеть от загрузки шрифта. Один файл на обе темы: `fill="currentColor"`, цвет из CSS (`var(--accent)`).
- **Вставка компонентом через `vite-svg-loader`, а не `<img>`** — в `<img>` `currentColor` резолвится в чёрный.
- **Имя для скринридера — в месте использования** (`role="img"`, `aria-label`, переводится через `t()`): `<title>` внутри файла выбрасывает SVGO плагином `removeTitle`.
- **Иероглиф 次** — второй знак, шрифт Zen Maru Gothic в кривых (`logoHieroglyph.svg`), устроен так же; рядом с логотипом скрыт `aria-hidden`, чтобы название не читалось дважды.
- **Фавиконка** — тот же иероглиф, `public/favicon.svg`, но цвет задан числом: вне страницы `currentColor` дал бы чёрный. Начертание жирное — на 16px тонкие штрихи сливаются.
- **Не сделано:** `apple-touch-icon.png` 180×180 — iOS не берёт SVG для значка на домашнем экране. `.ico` не нужен.

| ----------------- | ------------------------ | -------------------------------------- |

| `/schedule`       | Расписание выхода серий  | да                                     |
| `/search`         | Поиск по строке, каталог | да, фильтры — после MVP                |
| `/anime/:id`      | Детали тайтла            | да                                     |

Переход на `createWebHistory` дал бы адреса без `#`, но потребует правила в `vercel.json`: любой путь отдавать как `index.html`, иначе прямая ссылка `/schedule` вернёт 404 от хостинга. Не приоритет: на работу приложения не влияет.

### Структура файлов

```
src/
  api/           слой доступа к данным, о UI не знает ничего: клиент, функция запроса
    gql/         тексты запросов и фрагментов
    generated/   вывод codegen, руками не редактируется
  stores/        Pinia: состояние, кеш, вызовы api — по стору на предметную область
  views/         компоненты-страницы, по одному на роут
  components/    общие компоненты — в корне, принадлежащие одному экрану — в папке экрана
  composables/   переиспользуемая реактивная логика (useXxx)
  constants/     константы, например themeOverrides для Naive UI
  utils/         чистые функции: ни реактивности, ни сети, ни DOM
  router/
  locales/       vue-i18n, ru и en
  styles/        reset, тема, SCSS-переменные и миксины
  assets/        статика, импортируемая из кода
  types/         собственные минимальные типы, не связанные с API напрямую
```

### Принципы

**Поток данных в одну сторону: `api → stores → views/components`.** Компонент не обращается к `api` напрямую, только через стор. Причина практическая: загрузка, ошибка и кеш живут в одном месте. Иначе два компонента, которым нужны одни данные, запросят их дважды и каждый будет крутить свой скелетон.

**Исключение — подсказки в шапке** (`SearchAutocomplete`). Они ходят в `api` сами, мимо стора: их состояние живёт секунды, другим компонентам не нужно, в адрес не пишется (5.3). Попытка положить их в общий стор с выдачей страницы поиска сломала её: ввод в шапке перетирал сохранённую выдачу (05.10.2026).

**Зависимости направлены внутрь.** `api/` не знает о компонентах. `utils/` не знает ни о чём — функции там принимают минимальные структурные типы, а не сгенерированные, и поэтому не ломаются при перегенерации схемы и тестируются без окружения.

**Файл на предмет, а не свалка.** Никакого `utils/index.ts`, куда складывается всё. Имя файла отвечает на вопрос «про что», а не «какого технического рода». Когда в одном файле набирается больше пяти функций про разные вещи — делить по предметам.

**Запросы живут в `api/gql/`, не рядом с компонентами.** Кроме порядка, есть техническая причина: `documents` в `codegen.ts` указывает только на эту папку, поэтому синтаксическая ошибка в компоненте не ломает генерацию типов.

**`api/generated/` не редактируется руками** — при следующем запуске `npm run codegen` правки исчезнут. Файл при этом **коммитится**: иначе сборка на чистой машине и деплой начинают зависеть от доступности AniList. Риск расхождения будет закрываться проверкой в CI (11.2, пока CI нет): перегенерировать и упасть, если результат отличается от закоммиченного. В `.gitattributes` помечен как `linguist-generated`, чтобы не засорять диффы.

**`views/` против `components/`.** В `views/` попадает только то, что подключено в роутере, один файл на роут. Остальное — в `components/`, даже если компонент используется одной страницей. Общие компоненты (`CoverCard`, `TitleCard`, `TitleImage`, `CustomResult` и т. п.) лежат в корне `components/`, принадлежащие одному экрану — в папке экрана: `Carousel/`, `Home/`, `Schedule/`, `Search/`.

**Стили подключаются в двух местах.** `variables` и `mixins` инжектятся в каждый SCSS-блок через `additionalData` в `vite.config.ts` — поэтому в компонентах можно писать `$base-padding` без импорта; это не магия Vue, а настройка сборки. `reset` и `theme` подключаются один раз в `main.ts`: в них правила, а не переменные, и инжект в каждый блок размножил бы их по всем компонентам.

**Заранее ничего не создаём.** Папка или абстракция появляется, когда возникает второй случай с одинаковым поведением, а не в ожидании этого. Так появился и `composables/`: `useAbortController` вынесен, когда отмена понадобилась и стору тайтла, и поиску.

## 5. Экраны

Для каждого экрана обязательны четыре состояния: **loading**, **error + повтор**, **empty**, **success**. Отсутствие empty- и error-состояний — самая частая претензия на ревью.

### 5.1 Главная `/`

**Зачем экран (решено 11.09.2026):** главная — про **тебя**, расписание — про всех. Пять раскладок подряд, задуманных как «что выходит сейчас», выходили уменьшенной копией `/schedule`; своя работа нашлась в §1 — расписание с привязкой к личному списку. Без списка (MVP) главная — полоса «Сегодня» и популярное.

Помнить при любой правке: `airingAt` — это японский эфир. Отсчёт обещает «вышло в Японии», а не «посмотришь», поэтому отсчёт не делается главным объектом страницы.

#### Состав сверху вниз

| Блок                          | Когда виден         | Содержимое                                                             |
| ----------------------------- | ------------------- | ---------------------------------------------------------------------- |
| Приглашение подключить список | список не подключён | плашка «Указать ник» с крестиком — после MVP                           |
| «Твои релизы»                 | список подключён    | ближайшая своя серия крупно, отсчёт, два счётчика — после MVP          |
| «Сегодня»                     | всегда              | полоса обложек по времени, ссылка «Всё расписание» на `/schedule?day=` |
| «Популярное сейчас»           | всегда              | баннер первого тайтла, сетка `TitleCard`, «Весь каталог» → `/search`   |

Личный блок — надстройка сверху: всё ниже одинаково со списком и без, двух раскладок нет. Делить надо не «авторизован / нет» (авторизации в MVP нет), а «список подключён / нет».

**Тайтлы 18+** в полосе и в популярном не отфильтровываются, а показываются с размытой обложкой (5.4).

#### Полоса «Сегодня»

Данные — неделя из `useScheduleStore`, кеш общий с расписанием, отдельного запроса нет.

- **Всегда сегодняшняя** (11.09.2026): на другой день не переключается; если релизов нет — пусто. Подмена дня под заголовком «Сегодня» врала бы.
- **Прокручивается к границе прошлого и будущего:** к первой невышедшей карточке, а если всё вышло — к последней.
- Вышедшее остаётся, приглушённым; отсчёт только у ближайшей карточки, у остальных время. Совпадение времени — обычный случай.
- Своих тайтлов в MVP нет. Когда появятся, отмечать их акцентной рамкой нельзя — она уже занята ближайшей серией.

**Ближайший релиз ищется по всей неделе, а не в дне:**

- сегодня — его карточка получает акцент и отсчёт, к ней прокрутка;
- в другой день — над полосой строка «Следующий выход — завтра в 10:00» или «— в среду в 10:00» (разрыв до шести дней, считается в календарных днях через `startOf('day')`, винительный падеж — свои ключи в локалях);
- не найден (воскресный вечер, следующей недели в кеше нет) — ни акцента, ни строки. Подгрузка соседней недели решила бы это; `loadWeek` для этого экспортирован.

**Планируется подсказка с датой** на строке «Следующий выход»: «в среду» через шесть дней читается хуже даты. Не сделано.

**Пустой день:** «Релизов нет», строка про следующий выход остаётся — иначе тупик.

**Это прокрутка, а не карусель** (11.09.2026): `n-carousel`, swiper и embla управляют слайдами как страницами и перехватывают touch. Обычная прокрутка даёт инерцию и клавиатуру даром; JS только для стрелок и автопрокрутки.

- Тихое обновление по TTL не возвращает полосу к началу: автопрокрутка следует за индексом ближайшей серии (`scrollToIndex` → `watch` в `CustomCarousel`), а не за приходом данных. Отдельного таймера нет — граница двигается от `useNow`.
- Прокрутка мгновенная (`instant`): плавная на загрузке выглядит как самопроизвольное движение. Открыто: переезд в момент выхода серии был бы уместнее плавным.
- Перетаскивание мышью не делаем — конфликтует с кликом по карточке.

**Отложено:** затухание по краям через `mask-image` — прячем полосу прокрутки, значит нужен другой признак, что блок листается; затухать только там, где есть продолжение. **Идея:** вместо рамки при наведении — лёгкое увеличение обложки (`transform: scale` внутри `overflow: hidden`, без него при `prefers-reduced-motion`); но рамка сейчас и есть отметка ближайшей карточки, это решать сознательно.

#### Популярное

- Запрос `GetTopAnime`, сортировка `TRENDING_DESC`, 20 тайтлов; первый с баннером — в баннер, остальные 14–15 — в сетку (баннер на экранах уже 700px скрыт, и его тайтл идёт в сетку).
- Сетка, а не карусель: горизонтальное движение на странице одно — у полосы «Сегодня». `auto-fit, minmax(150px, 1fr)`; карточки намеренно мельче поисковых, чтобы не спорить с полосой.
- Баннер только здесь: в расписании его нет у многих тайтлов, а `ScheduleMedia` его не запрашивает. У всех карточек подложка на время загрузки обложки — `coverImage.color`.
- Обложки — `extraLarge`: `large` (230px) мылит на телефонных экранах с плотностью 2–3 (замер 22.09.2026). Правило для всего приложения — всё крупнее миниатюры берёт `extraLarge`, `medium` только в подсказках поиска.

#### Личный блок «Твои релизы» — после MVP

Состояния: списка нет — приглашение; релизы есть — ближайшая своя серия крупно, отсчёт, «и ещё одна твоя в 21:00» при совпадении; на неделе ничего — блок остаётся с текстом, а не схлопывается, иначе страница прыгнет.

Крупный размер здесь честный: «следующее у тебя» — твоя подписка, а «следующее вообще» — случайный тайтл.

**Счётчики «Выходит сегодня» и «Выходит на этой неделе»** — пересечение списка с закешированной неделей, включая уже вышедшие серии. Число статично и читается как итог, не остаток; под ним строка состава «2 уже вышли» (скрыта при нуле, «все вышли» при полном). «Вышло, не отмечено» отвергнуто: без OAuth это считает аккуратность записей, а не реальность. Идея на потом — «с прошлого захода вышло N».

#### Что отвергнуто

- **Карусель сегодняшних релизов** — автопрокрутка уводит отсчёт раньше, чем его прочтёшь.
- **Крупный блок «ближайший релиз» и лента-барабан** — случайный тайтл получает незаслуженный размер, а выходят они пачками.
- **Вертикальная повестка дня** с линией «сейчас» — всё одного размера, глазу не за что зацепиться.
- **Корень сразу на расписание** — отвергнуто, когда у главной появилась своя работа.

#### Состояния

Скелетоны у блоков независимые: полоса смотрит в `loading` недели, популярное — в свой (проверено 14.10.2026).

**Ошибок нет ни у одного блока** (§9): при ошибке расписания полоса пишет «Релизов нет», будто их нет, а ошибка популярного только повод перезапросить при следующем заходе.

### 5.2 Расписание `/schedule` — ключевой экран

#### Режим просмотра

Шире 1240px — неделя из 7 колонок, уже — один день. Режим выбирает ширина окна, а не человек.

**Отзыв тестировщика (22.09.2026) — четыре претензии с одной причиной:** непонятно, что показана неделя; на широком экране нельзя посмотреть один день; при изменении ширины экран меняется сам; непонятно, зачем выбирать день в недельной сетке.

**Направление:** переключатель «Неделя / День», ширина задаёт только значение по умолчанию, режим в адресе (`?view=` рядом с `?day=`). Отложено.

**Сделано 09.10.2026** — закрыта последняя претензия:

- на широком экране кнопки дней некликабельны и не подсвечивают выбранный день — клик там ничего не давал;
- в узкой раскладке кнопка дня — ссылка (`RouterLink` с `replace`): фокус с клавиатуры, открытие в новой вкладке; выбор между ссылкой и блоком — через `<component :is>`;
- смена дня в узкой раскладке прокручивает наверх — осознанно, новый день смотрится с начала (`scrollBehavior`, 5.3);
- колонки недели разделены пунктиром посередине промежутка; линия заходит под кнопки дней и кончается вместе с колонкой. Вариант сильнее — подложка от кнопки на всю колонку — может вернуться после MVP.

#### Раскладки

**Широкая (≥1240px):** 7 колонок, понедельник — воскресенье; в колонке заголовок дня и карточки по времени эфира.

**Узкая (<1240px):** полоса дней как навигация (день, число, счётчик релизов), под ней — выбранный день строчными карточками (обложка слева, текст справа), сетка `n-grid` `cols="1 650:2"`.

**Почему 1240.** При сужении колонки деградирует не подпись времени, а название: оно превращается в лестницу — 5 строк на 157px, 7 на 126px (замер 27.08.2026). Минимум, при котором отсчёт «через 23 ч 59 мин» стоит одной строкой, — около 1145px.

**Почему строчная карточка в узкой раскладке.** Её высота не зависит от ширины, а вертикальная с обложкой 2:3 растёт вместе с колонкой. На 375px обе вмещают по 4 карточки на экран, шире строчная выигрывает. Обложка в ней 120px — на 85px тайтл не узнавался. Карточка одна (`ReleaseEpisodeCard`), вид переключается пропом `direction`.

**650 — ширина сетки, а не окна:** у `n-grid` по умолчанию `responsive="self"`, поэтому отступы и полоса прокрутки не влияют. Режим `screen` с числовыми ступенями не работает — Naive ждёт там свои имена брейкпоинтов и молча откатывается к одной колонке.

**Название не обрезается** (`line-clamp` отвергнут): в конце названий стоит «Season 2» — то, по чему тайтлы различают.

**Перенос дней в два ряда отвергнут:** второй ряд оказался бы ниже всех карточек первого, и «вся неделя перед глазами» теряется.

#### Шапка и липкость

**Ряд заголовков дней прилипает целиком** (своя сетка, отдельная от карточек), в обеих раскладках. Условия: `top` равен высоте шапки приложения (`$header-height`), `z-index` меньше её 10, фон кнопок непрозрачный, у предков нет `overflow`, кроме `visible`, — иначе `sticky` молча не работает.

**Зазор под шапкой гасится градиентом** от `var(--bg)` к прозрачности — это `::before` липкой шапки расписания (`z-index: -1` внутри шапки с `z-index: 9`). Прозрачный зазор, сплошная заливка и прилипание вплотную отвергнуты по виду; у прямоугольной заслонки ещё и конфликт со скруглением кнопок.

**Подсветки** (как в датапикере): сегодня — акцентный текст и полоса 5px снизу; выбранный день — рамка и фон, только в узкой раскладке.

**Заголовок:** на широком экране — диапазон недели, на узком — выбранный день («Расписание на 14 октября», с 09.10.2026). Кнопки «<», «Сегодня», «>» размера `large` (40px); растут, только когда переносятся на свою строку (`flex-grow` 15 к 1 у заголовка и кнопок, `flex-shrink: 0` у кнопок).

**Сокрытие шапки приложения при прокрутке** отложено до мобильной итерации: выигрыш около 60px из 812.

#### Адрес и навигация

**Один параметр `?day=YYYY-MM-DD`**, разбор строгий (`dayjs(raw, 'YYYY-MM-DD', true)`), неделя вычисляется из дня. Два параметра (`week` + `day`) порождают невозможные сочетания. Без строгости dayjs «перекатывает» даты: `2026-13-01` становится январём 2027.

**Мусор, пустое значение, дата за границей — молча сегодня;** при повторе параметра берётся первое валидное. Адрес формирует приложение, поэтому нарушение — битая ссылка, а не ошибка человека.

**Ключ кеша — понедельник недели** (`isoWeek`, `getStartOfWeekDate`): семь дней недели — один запрос.

**Вперёд — не дальше полугода от сегодня, назад без ограничения.** Каждая неделя — запрос при минутном лимите API; прошлое не меняется, и старые ссылки обязаны открываться. На границе стрелка «вперёд» гаснет.

**Данных впереди становится меньше, но ноль не наступает** (замер 28.08.2026: 100+ эпизодов в неделю на два месяца вперёд, около 40 через три-четыре, 5–7 через год). Поэтому отдельное «расписание ещё не опубликовано» не нужно — хватит «на этой неделе релизов нет».

**Навигация:** стрелки сдвигают на ±7 дней с сохранением дня недели, через `push` — это переход на другой отрезок, и «назад» его ожидаемо отменяет. «Сегодня» пишет сегодняшнюю дату и гаснет, когда она уже выбрана. Смена дня — `replace`: «назад» возвращает на прошлый экран, а не листает дни.

#### Карточка эпизода

`ReleaseEpisodeCard`: обложка `extraLarge`, название, номер эпизода, время эфира в локальной зоне, на нём подсказка с полной датой и часовым поясом. Клик — на `/anime/:id`.

**Тайтлы 18+** не отфильтровываются: до согласия обложка размыта, клик по ней спрашивает согласие, переход — по названию; счётчики дней такие эпизоды учитывают (5.4).

**Обложка — `object-fit: cover` + `extraLarge`.** `large` (230px) не хватает даже вертикальным обложкам в карточке 236px; горизонтальные при обрезке слегка мягкие при любом разрешении (замер 19.08.2026).

**Состояния — прошлое помечаем, ближайшее будущее считаем, далёкое просто показываем:**

- время эфира — всегда;
- «вышло» — эпизод в прошлом: текстом и полосой `--success` по краю карточки (справа в строчной, снизу в вертикальной);
- отсчёт «через N ч M мин» — только сегодня и только до выхода; на будущей неделе он бесполезен, а 96 одинаковых подписей — шум.

**Приглушение вышедших (`opacity`) отменено 28.08.2026:** оно роняло контраст подписей вдвое ниже нормы WCAG, к концу недели накрывало почти все карточки и дублировало метку «вышло». Полоса по краю подсмотрена у YummyAnime: помечаем случившееся, а не притеняем остальное.

**Формат отсчёта:** до часа минуты, до суток часы и минуты, дальше дни; сокращения «мин», «ч», «д» — не склоняются и короче. Минуты округляются вверх, иначе последнюю минуту видно «через 0 мин». Подпись отсчёта не переносится — переносится время эфира. Сейчас это выполняется за счёт запаса ширины; если порог раскладки опустят, понадобятся `flex-shrink: 0` и `white-space: nowrap`.

**Счётчик релизов** — бейдж `n-badge` на углу кнопки дня. На узких экранах двузначный бейдж задевает название дня (§9).

**Тикер:** композабл `useNow`, один интервал на приложение, раз в 30 секунд.

#### Идеи, не реализовано

- **Подскролл к ближайшей серии** при открытии сегодняшнего дня (записано 21.09.2026): в день бывает до 30 релизов, и человек попадает на давно вышедшее. Граница прошлого и будущего уже считается для главной (5.1); открытый вопрос — карточка не должна уезжать под липкий заголовок.
- **Фильтр «уже вышедшие»** (только вышедшие / только предстоящие / все) — открытые вопросы в §9.
- **Фильтр «Только мой список»** — после MVP, вместе с `/my-list`.
- **Переход на произвольную неделю** через датапикер (`n-date-picker type="week"`, ключ — `toDateKey(dayjs(ts))`). Закомментированная заготовка в `ScheduleHeader.vue` удалена 16.10.2026.

#### Состояния экрана

Скелетон-сетка из 7 колонок; ошибка с кнопкой повтора; «на этой неделе релизов нет». **Пока не так:** пустая неделя показывает семь колонок с «нет релизов», а скелетоны широкой сетки — по одному блоку на колонку (§9). День без релизов в непустой неделе остаётся колонкой с «нет релизов» — дни из сетки не выпадают.

### 5.3 Поиск

Два инструмента: быстрый поиск в шапке — попасть на тайтл, страница `/search` — выдача и каталог. **Они независимы** (решено 12.10.2026; до этого планировалась синхронизация через `q`, как у YummyAnime): шапка не читает `q` из адреса и не очищается при переходе, выпадашка работает и на самой `/search`.

#### Быстрый поиск в шапке

Только по тексту: набрал — выбрал из выпадашки — открылся тайтл.

- **Подсказки с трёх символов,** с дебаунсом; одна-две буквы вернули бы мусор и сожгли лимит.
- **Выбор пункта — переход, строка сохраняется** (10.09.2026): открыл тайтл, вернулся, выбрал соседний без перенабора.
- **У Enter два смысла:** подсвечен пункт — открывается тайтл, нет — `/search?q=…`. Выпадашка собрана из `n-popover` и `n-input` со своей обработкой ↑ ↓ Enter Escape (`n-auto-complete` не используется).
- **В адрес не пишется:** строка живёт секунды, пересылать её незачем.
- **Ответы упорядочены отменой предыдущего запроса** — дебаунс уменьшает число запросов, но не порядок ответов.
- **Переход гасит оба хвоста** (07.10.2026) — отложенный вызов дебаунса и запрос в пути; иначе ответ после перехода заново открывал выпадашку на новой странице. Escape и клик мимо только прячут список.
- **Ошибка — всплывашка:** действие запустил человек, а места под состояние в выпадашке нет.
- **Запрос общий со страницей поиска** (`search`, фрагмент `SearchListMedia`, 20 штук). Лишние поля — строки в JSON, а не картинки: подсказка скачивает только `medium`. Компромисс 07.10.2026, разделить можно позже.
- Подсказки ходят в `api` мимо стора — исключение из правила потока данных (§4).
- **Тайтлы 18+** — с размытой миниатюрой; блюр здесь не снимается: строка ведёт на тайтл, согласие даётся там (5.4).

**Не сделано:** кнопка рядом с полем, открывающая каталог в любой момент; пока каталог открывается ссылкой «Весь каталог» на главной. Мобильная вёрстка шапки — отдельным заходом (10.09.2026): на 375px поле не помещается, обычное решение — свернуть поиск в иконку, раскрывающую поле поверх шапки.

#### Страница `/search`

**В MVP — только строка, без фильтров** (05.10.2026). Задуманные фильтры на следующую итерацию: жанры, год, сезон, формат, статус, сортировка. Все они будут в query-параметрах через `router.replace` и восстанавливаться из адреса.

- **Поиск по Enter, без дебаунса** (07.10.2026): Enter кладёт строку в `?q=` через `replace`, остальное делает наблюдатель за адресом. Строка из одних пробелов — каталог; пробелы по краям в поле не трогаются, чтобы оно не менялось под рукой.
- **Пустая строка — каталог** (10.09.2026), в MVP — всё по популярности. Это не отдельное состояние, а обычная выдача.
- **Обрабатываются только ссылки, которые создаёт приложение** (`q` нет или непустая строка) — их могут переслать; ручные `?q=` и `?q` не перебираем.
- **Счётчика «Найдено N» нет:** `total` у AniList нечёткий — по «frieren» он вернул 5000.
- **Тайтлы 18+** в выдаче не отфильтровываются, а показываются с размытой обложкой (5.4).

**Выдача: «Показать ещё» + выдача в сторе** (05.10.2026). Сетка `TitleCard` до шести колонок, на 360px две, по 12 за раз. Стор держит последнюю выдачу, и при возврате с тайтла с той же строкой запроса нет. Признак «ещё не загружали» — `undefined` в фильтре стора: `null` занят каталогом.

Почему так, а не иначе. Главное на этом экране — **сохраняется ли выдача при возврате с тайтла**, это самое частое действие (разбор 10.09.2026). Пагинация решала бы это номером страницы в адресе, но склонились к «Показать ещё» — листать удобнее. Вариант YummyAnime отвергнут: там помнят число страниц и при возврате перезапрашивают все, а у AniList минутный лимит.

**Прокрутка** (замер 09.10.2026): при возврате позицию восстанавливает и браузер — выдача из стора рисуется сразу. Но без `scrollBehavior` новый переход наследовал прокрутку прошлой страницы, и тайтл из низа каталога открывался внизу. Правило роутера: есть `savedPosition` («назад» / «вперёд») — он, иначе наверх.

**Состояния** (08.10.2026):

- первая загрузка — скелетоны в форме карточки (обложка 2:3 и строка под название);
- ничего не нашлось — `CustomResult` с кнопкой «Весь каталог»;
- ошибка экрана — `CustomResult` с повтором, иконка как на странице тайтла;
- дозагрузка — спиннер в кнопке «Показать ещё»;
- ошибка дозагрузки — всплывашка, кнопка остаётся повтором: блок на весь экран посреди сетки читался бы как «пропало всё».

`CustomResult` — когда состояние заменяет выдачу целиком, и стоит он рядом с сеткой, а не внутри неё.

### 5.4 Детали `/anime/:id`

#### Раскладка (утверждена 22.09.2026), сверху вниз

1. **Баннер** `bannerImage` во всю ширину, `object-fit: cover`: пропорции исходников гуляют (1900×400, 1800×550, 1721×391), опираться на них нельзя. Высота — от ширины окна с ограничителями, цель `clamp(140px, 18vw, 340px)`; **сейчас в коде `min(20vw, 25vh)` без нижней границы** (см. «Мобильная вёрстка»).
2. **Обложка** `extraLarge` отрицательным отступом наезжает на баннер. Справа — название (`getMediaTitle`: `english` → `romaji` → `native`, без учёта локали), под ним «`romaji` · `native`», ниже бейджи: формат и год, статус, оценка.
3. **Полоса ближайшей серии**, зелёная (`--success`, цвет релизного состояния): «Серия 13 выйдет в четверг, 24 сентября, в 18:30», ниже «через 2 дня», рядом «вышло N из M». Данные — из `nextAiringEpisode`, а не из первой будущей записи расписания: у длинных сериалов оно начинается позапрошлым годом.
4. **Две колонки:** слева факты (`flex: 1 1 30%`, не уже 250px) — студия (`isMain`), эпизоды, длительность, сезон, начало и окончание показа, первоисточник, «в списках» (`popularity`); справа жанры и описание со сворачиванием. Вторую оценку не выводим — она уже в бейдже.
5. **«Ближайшие выходы»** под разделителем.

**Нет баннера — плашка цвета `coverImage.color`, нет и цвета — `var(--accent)`** (05.10.2026). Раскладка при этом не меняется. Пустой баннер не редкость: его нет почти у четверти тайтлов в глубине каталога (замер 02.10.2026), и без цвета бывают даже свежие тайтлы. `--cover-color` всегда выставляется с откатом на акцент, поэтому и вуаль над баннером тогда фиолетовая — на вид неотличимо от нейтральной.

**Страница читательская, действий нет.** Место под будущие кнопки `/my-list` — под обложкой, над фактами: появление кнопки сдвинет только колонку фактов. Заглушку не рисовать: серая кнопка «скоро» выглядит брошенной работой. Ссылку на AniList не ставим — источник указывается в подвале.

**Жанры** со временем станут ссылками на поиск с фильтром; фильтров в MVP нет, поэтому теги неактивные.

#### «Ближайшие выходы»

Список строк «серия N — день, дата — время — через сколько», по умолчанию четыре, остальные по кнопке. Горизонтальная лента отвергнута: плитки отличались бы только датой.

- Показывается, когда будущих серий больше одной: одна уже написана в полосе выше. Условие по статусу хуже — выкинуло бы анонсы с известной датой.
- Запрос `airingSchedule(notYetAired: true)`, одна страница: у двенадцати самых популярных выходящих `hasNextPage: false`, даже у One Piece.
- «Вышло N из M» — из `nextAiringEpisode.episode − 1`; при `episodes: null` «из M» пропадает.

**Полного списка серий нет, и правила на случай, если его сделают** (замер 22.09.2026):

- рисовать только пришедшие записи, не цикл от 1 до `episodes` — у Frieren записи начинаются с пятой серии;
- у тайтлов примерно до 2015 года расписания нет вовсе — пустой список это норма;
- `pageInfo` вложенного `airingSchedule` врёт (у One Piece `total` гуляет между 450 и 500, `perPage` режется до 25); конец — когда пришло меньше 25 записей.

#### Трейлер — не сделано, низкий приоритет

`trailer` запрашивается почти всегда заполненным (YouTube, с `thumbnail`), но на странице не выводится. Место — правая колонка под описанием.

- **Делать стоит, хоть из России YouTube без VPN и замедлен:** это ограничение доступа в стране зрителя, а не дефект приложения, и неиграющий плеер YouTube зритель с ним и свяжет — как это выглядит без VPN, все знают.
- **`<iframe>` — только по клику**, до этого превью с кнопкой: иначе YouTube получает данные обо всех, кто просто открыл страницу, а бандл и так тяжёлый.
- **`trailer.id` не кодировать:** у «Атаки титанов» в нём хвостовая табуляция, которую браузер сам вырезает из URL, а `encodeURIComponent` превратит её в `%09` и сломает ссылку. `.trim()` — как гигиена.
- `trailer.site` может быть `dailymotion` — пропускать не-YouTube явно.
- Превью — напрямую с `i.ytimg.com`: прокси через Vercel убирается (6.2).

#### Взрослый контент — на всех экранах, не сделано

**Блюр вместо фильтра (решено 16.10.2026).** Тайтлы 18+ (`isAdult`) не отсекаются из списков, а показываются с размытой обложкой везде, где есть обложки: в полосе «Сегодня» и популярном (5.1), в расписании (5.2), в подсказках и выдаче поиска (5.3), на странице тайтла. До этого поведений было три: расписание фильтровало на клиенте, популярное и поиск — на сервере (`isAdult: false` в запросе), а страница тайтла по прямой ссылке не защищалась никак. Теперь механизм один, а расписание показывает все выходы недели.

**Сколько их на самом деле** (замер 16.10.2026, недели с 21.09 по 18.10): в расписании 1–6 взрослых эпизодов в неделю из 97–117; в трендах (первые 20), каталоге по популярности (первые 150) и выдаче по общим словам (первые 12) — ни одного; поиск по точному названию их находит. На практике блюр встретится почти только в расписании и в полосе «Сегодня».

**Поведение:**

- **визуальный барьер, а не проверка возраста:** обложка размыта (на странице тайтла — баннер и обложка), поверх — кнопка-накладка (`button` с `aria-label`), клик открывает `n-popconfirm`, согласие снимает блюр;
- **вид накладки** (16.10.2026): блюр затемнён на 45%, по центру — белая иконка перечёркнутого глаза (`VisibilityOffRound` из `@vicons/material`), текста нет, смысл для скринридера несёт `aria-label`. Затемнение подобрано на стенде из шести обложек, от почти белой до тёмной: иконка — единственный признак кнопки, ей нужен контраст не ниже 3:1 (WCAG 1.4.11). На почти белой обложке 45% дают около 3,4:1, привычные 25–30% — около 2:1, а без затемнения белая иконка на светлых обложках пропадает. Кружок под иконкой (около 4:1) и тень у иконки отвергнуты по виду;
- **плашки в углах обложки остаются чёткими** поверх блюра — номер эпизода и время, оценка, формат и год: в них нет ничего откровенного, а без них карточка теряет свои данные;
- **текст подтверждения:** «Тайтл для взрослых. Вам уже есть 18?», под ним мельче — «Ответ запомним на сутки», чтобы было понятно, сколько действует согласие; кнопки «Отмена» и «Да, показать»;
- **клик по заблюренной обложке только спрашивает согласие** и на тайтл не ведёт. Переход — по названию, поэтому название не скрывается. Кнопка-накладка стоит рядом со ссылкой-названием, а не внутри ссылки: интерактивный элемент внутри `<a>` недопустим. Чтобы переход было видно, название заблюренной карточки подчёркивается при наведении; у обычной карточки ссылка — вся карточка, и подчёркивания нет;
- **после согласия карточка ничем не отличается от обычной:** вся карточка — ссылка, обложка тоже ведёт на тайтл. Значит, у `CoverCard` и `ReleaseEpisodeCard` два вида разметки, и они переключаются по согласию;
- **согласие на одной карточке сразу снимает блюр со всех** на экране, без перезагрузки;
- **фокус после согласия возвращается на ту карточку, на которой нажали:** кнопка, на которой он стоял, исчезает, и без этого фокус падает на `body` — для клавиатуры и скринридера это «выкинуло в начало страницы»;
- **в подсказках быстрого поиска блюр не снимается:** строка и есть название и ведёт на тайтл, согласие даётся уже там. После согласия миниатюры в подсказках тоже открываются — согласие общее.

**Согласие и техника** (22.09.2026):

- **флаг один на приложение** в `localStorage` — момент, до которого согласие действует (сутки). `sessionStorage` отвергнут: тайтлы открывают в новых вкладках пачками. Чтение — в `try`, мусор даёт `NaN` и считается просроченным;
- размытие косметическое: файл всё равно скачивается. Если понадобится «не отдавать» — не подставлять `src` до согласия;
- кайма от `filter: blur()` лечится увеличением слоя и `overflow: hidden`.

**Данные:** `isAdult` должен приходить во всех запросах, где есть карточки; серверный фильтр (`isAdult: false`) и клиентский фильтр стора расписания убираются.

#### Состояния

Скелетоны при загрузке. «Такого тайтла нет» и «нет связи» различаются: на несуществующий `id` AniList отвечает HTTP 404 с `Media: null` (замер 22.09.2026), и статус доходит до страницы. Переменная `id` объявлена `Int!`, чтобы пропуск отсекался на клиенте.

#### Мобильная вёрстка — открыто

Баннер здесь и есть шапка, убрать его нельзя. Читаемость ломается между 640 и 480px: обложка держит фиксированную ширину и забирает больше половины экрана, название уходит в 3–5 строк (замер 02.10.2026). Горизонтальной прокрутки нет.

- **Нижней границы высоты баннера нет:** на окне 399px он 75px — полоска, а не шапка, и обложка почти не заходит на него. Осмысленный минимум — 140–175px.
- Оба варианта шапки (бейджи рядом с обложкой и название под ней; название в узкой колонке рядом с обложкой) отвергнуты 02.10.2026, решения нет.
- С фактов и описания нужно снять `:wrap="false"`, иначе они делят узкую строку.

### 5.5 Мой список `/my-list` — после MVP

**Экран вырезан из первой версии (18.09.2026).** Ниже — проработанное устройство на следующую итерацию; в коде его нет.

#### Источник данных

У AniList две разные сущности: **MediaList** (статус, прогресс, оценка; запись — `SaveMediaListEntry`, чтение — `MediaListCollection(userName:, type: ANIME)`) и **Favourites** (просто отметки). Нужен MediaList. Запись требует авторизации, чтение публичного списка по нику — нет.

**Без OAuth (он в 11.3) список собирается из двух слоёв:**

- **публичный список AniList по нику** — только чтение, в кеше с TTL, всегда можно перезапросить;
- **локальные пометки в `localStorage`** — единственная копия, в аккаунт AniList не уезжает.

Слои сливаются в один объект по `mediaId`, локальное поверх: при конфликте побеждает более свежее явное действие в приложении. У записи есть признак источника (`'anilist' | 'local'`) — чтобы показать, что пометка не сохранена в аккаунте, и чтобы «Отключить AniList» убирало только свой слой.

#### Где указывается ник

- **Здесь, на этом экране** — поле и «Загрузить»; после подключения «Список AniList: ник» и «Отключить».
- **Расписание** формы не имеет: при фильтре «только мой список» без ника и пометок — подсказка со ссылкой сюда.
- **Главная** — плашка-приглашение «Указать ник», закрывается навсегда; это безопасно, потому что канонический вход — пункт меню «Мой список».

**Ник в адресе важнее сохранённого:** `/schedule?user=ник` показывает список этого человека (так работает шаринг), без параметра берётся ник из `localStorage`, и чужой ник из адреса сохранённый не перетирает. Этот же механизм нужен сравнению списков (11.4).

#### Чтение и ошибки

`MediaListCollection` отдаёт записи по пользовательским категориям — их схлопывают в плоский набор `mediaId`, `status`, `progress`, `score`. Сообщения различаются: нет такого ника — «Пользователь не найден»; список закрыт — пустой ответ, и это «Список закрыт настройками приватности», а не «список пуст», иначе выглядит поломкой.

#### Хранение

- **Статусы под именами AniList** (`MediaListStatus`: `CURRENT`, `PLANNING`, `COMPLETED`, `DROPPED`, `PAUSED`, `REPEATING`), подписи — только в локалях. Данные AniList ложатся в модель без преобразования, а переход на OAuth меняет источник, а не модель.
- **Форма:** `{ version: 1, items: { [mediaId]: { status, progress, score?, updatedAt } } }`. Объект, а не массив: расписание проверяет «в моём списке» на каждой карточке, по ключу это дёшево.
- **Синхронизация:** `watch` на стор с `deep: true` → `localStorage.setItem`, чтение при инициализации стора.
- **`localStorage` — недоверенный ввод:** разбор в `try/catch`, проверка формы и `version`; при несовпадении — пустой список, а не падение.

#### Экран

Группировка по статусам, у каждого тайтла прогресс по эпизодам. Пустой список — приглашение в каталог.

## 6. Работа с API

### 6.1 Клиент

Axios-инстанс на `https://graphql.anilist.co`, POST-запросы вида `{ query, variables }`. Интерсептор ответа: проверка `data.errors` (GraphQL отдаёт HTTP 200 даже при ошибке — это отдельная ловушка), приведение к единому виду ошибки.

**Клиент ошибки не показывает (решено 30.08.2026).** Он отклоняет промис и отдаёт отказ наверх как есть — показывает тот, кто знает контекст. Всплывашка из интерсептора убрана (вместе с `createDiscreteApi` в клиенте): она мешала фоновому обновлению быть тихим (6.4) и не знала про тему приложения, поэтому в тёмной теме выходила светлой плашкой. Внутри приложения эту роль играет `useMessage()`, у него такой проблемы нет.

Где всплывашки есть сейчас (14.10.2026): быстрый поиск в шапке и ошибка дозагрузки на `/search` — через `useMessage()`; страница тайтла — через `createDiscreteApi` прямо в сторе `animeCard.ts`. Последнее — тот же приём, от которого клиент отказался: отдельный экземпляр со своей копией темы; стоит перевести на `useMessage()` в компоненте (§9). У расписания своё пустое состояние с кнопкой повтора, на главной ошибка не показывается вовсе — записано в долге.

**Открытый вопрос:** пустое состояние говорит «данные потеряны» при любой ошибке, поэтому при `429` человек будет жать «Повторить» и получать тот же отказ. Причина отказа должна жить в постоянном состоянии, а не во временной всплывашке. Отложено.

### Лимит запросов — справка

**Решение по обработке отложено.** Ниже только собранные факты, чтобы не выяснять их заново. Реализация — когда до неё дойдут руки.

**Лимит — 30 запросов в минуту.** Документация заявляет 90, но тут же оговаривает, что API «в деградированном состоянии» и ограничен 30. Замер 16.08.2026 подтверждает: `x-ratelimit-limit: 30`. Таймаут после превышения — одна минута. Тело ошибки: `{"message": "Too Many Requests.", "status": 429}`.

**Заголовки по документации:** `X-RateLimit-Limit` и `X-RateLimit-Remaining` приходят всегда; `Retry-After` (секунды) и `X-RateLimit-Reset` (unix-таймстемп) — только при 429.

**Браузеру видно не всё.** Замеренный читаемый набор на успешном ответе: `cache-control`, `content-type`, `x-ratelimit-limit`, `x-ratelimit-remaining`. Первые два открыты спецификацией, значит AniList явно выставляет наружу только два своих — `Retry-After` и `X-RateLimit-Reset` через `Access-Control-Expose-Headers` не открыты.

**Два разных вида отказа.** Обычно приходит честный `429`, доступный как `error.response.status`. При резком всплеске запросов ответ приходит вообще без CORS-заголовков, и до скрипта не доходит: `error.response` отсутствует, `error.code` равен `ERR_NETWORK`, причина неотличима от отсутствия сети.

**Насколько это вообще актуально.** При работающем кеше недель обычный сценарий использования в лимит не упирается — 30 запросов в минуту набираются только целенаправленным перебором. В упомянутом замере лимит был выбит диагностикой, а не обычным пользованием.

**403 без заголовка `Referer` (10.09.2026).** На время своих проблем со стабильностью AniList начал отвечать `403` с текстом «The AniList API has been temporarily disabled» на запросы без `Referer`. Замерено: `User-Agent` и `Origin` не помогают, любой `Referer` — включая `http://localhost:5173/` и `https://example.com/` — даёт `200`. Похоже на грубый фильтр ботов, а не на проверку домена.

Приложения это не касается: браузер подставляет `Referer` сам, исходя из адреса страницы. А вот **кодогенерация ходит за схемой из Node**, без браузера, и потому упиралась в отказ — отсюда заголовок в `codegen.ts`. Значение там любое и от адреса развёртывания не зависит: `codegen` выполняется на машине разработчика, а не на сервере.

### 6.2 Прокси через Vercel — решено убрать

**Решено убрать (16.10.2026).** Без VPN из России не открывается сам Vercel, поэтому переписывание путей помогает только в редкие моменты, когда домен всё же доступен; с VPN AniList и его картинки доступны напрямую. Цена известна: если домен без VPN откроется, обложки будут пустыми, а запросы повиснут. Взамен — один путь в разработке и в бою: проверки `import.meta.env.PROD` в `client.ts` и `proxyImageUrl` уходят вместе с оговоркой «путь через прокси не проверяется локально», а картинки не расходуют трафик Vercel. Если понадобится доступ без VPN, это вопрос выбора хостинга, а не прокси.

Ниже — как было устроено, для истории.

**Решено 22.09.2026, после выкладки.** Из России `s4.anilist.co` недоступен — картинки не грузились вовсе. Запросы к `graphql.anilist.co` формально проходили, но часть висела без ответа и обрывалась по таймауту клиента. Для портфолио это смертельно: ревьюер открывает ссылку и видит пустоту.

Решение — **переписывание путей на стороне хостинга, без серверного кода.** В `vercel.json`:

| Путь в приложении | Куда уходит                    |
| ----------------- | ------------------------------ |
| `/img/:path*`     | `https://s4.anilist.co/:path*` |
| `/api/anilist`    | `https://graphql.anilist.co`   |

Браузер обращается только к собственному домену приложения, а за границу ходит уже машина Vercel. Открытым прокси это не становится: адрес назначения зашит в правило, произвольный хост через него не запросить.

**В разработке прокси не используется — и это принципиально.** Прокси для dev-сервера крутился бы на локальной машине, то есть последний участок пути упирался бы в ту же блокировку, только с лишним звеном: картинки грузятся медленно, запросы падают. Поэтому и в `client.ts`, и в `proxyImageUrl` стоит проверка `import.meta.env.PROD`, а в `vite.config.ts` никакого `server.proxy` нет.

Следствие, о котором надо помнить: **путь через прокси не проверяется локально.** Ошибка в `vercel.json` видна только после выкладки. Смягчается тем, что каждая ветка на Vercel получает свой временный адрес, так что проверять правила можно, не трогая боевой.

Кодогенерации это не касается: она работает из Node и ходит к AniList напрямую, со своим заголовком `Referer` (раздел 2).

### 6.3 Запрос расписания

Запрос — `GetSchedule` в `api/gql/requests.ts`, на фрагментах `SchedulePageInfo` (`hasNextPage`), `AiringSchedules` (`id`, `airingAt`, `episode`, `media`) и `ScheduleMedia` (`id`, `title`, `coverImage { color large extraLarge }`, `isAdult`). Текст здесь не дублируется, чтобы не расходиться с кодом. `large` после перехода полосы «Сегодня» на `extraLarge` никем не читается — кандидат на удаление.

`perPage` у AniList максимум 50, а неделя релизов бывает больше сотни → **обязателен цикл по `hasNextPage`**, не один запрос.

**Плотность данных падает с удалением в будущее.** Замерено 10.08.2026:

| Неделя     | Записей | Ещё страницы |
| ---------- | ------- | ------------ |
| текущая    | 50      | да           |
| +5 недель  | 50      | да           |
| +13 недель | 38      | нет          |
| +22 недели | 15      | нет          |

Вещатели публикуют сетку на сезон вперёд, поэтому далёкие недели законно возвращают мало записей, а совсем далёкие — ноль. Это не ошибка загрузки, и интерфейс должен отличать «неделя загружена и пуста» от «неделя не загружена».

**`total` и `lastPage` доверять нельзя.** У ближних недель API отдаёт `total: 5000` и `lastPage: 100` — это потолок выдачи, а не настоящее количество. Признак конца — только `hasNextPage`.

### 6.4 Кеширование

| Данные            | TTL           | Где                                            |
| ----------------- | ------------- | ---------------------------------------------- |
| Расписание недели | 15 мин        | Pinia, `Map<weekKey, { data, fetchedAt }>`     |
| Популярное / топ  | без TTL       | Pinia; перезапрос, только если пусто/ошибка    |
| Детали тайтла     | нет кеша      | перезапрос на каждый заход                     |
| Результаты поиска | не кешируются | последняя выдача держится в сторе для возврата |

Прошлые недели можно кешировать бессрочно — они уже не изменятся. То есть TTL применяется не ко всем записям, а только к неделям, которые ещё не закончились.

Кеш живёт в памяти на время сессии. Персист в `localStorage` — в roadmap, не в MVP.

#### Как устроено обновление (решено 30.08.2026)

Запись недели хранит время **успешной** загрузки. Дальше два независимых вопроса: протухлость решает, идти ли в сеть, а наличие данных — шумно или тихо. Путать их нельзя: запись, упавшая на первой загрузке, протухшая, но за ней пустой экран, и обновлять её надо шумно.

- **Шумно** (показывать нечего): скелетон, при отказе состояние ошибки с кнопкой повтора.
- **Тихо** (данные есть, но устарели): старое остаётся на экране, запрос идёт фоном, замена по факту успеха. Приём известен как stale-while-revalidate.

**Отказ фонового обновления пользователю не показывается** — он его не запускал. Ошибка пишется в состояние только в шумной ветке и снимается по успеху. Время успешной загрузки при отказе не двигается, поэтому данные остаются протухшими и повтор случится сам при следующем обращении.

**Пометка возраста данных** вместо сообщения об отказе: «не удалось обновить» — событие, оно исчезает; «данные от 14:20» — состояние, верное всё время. Открыто: где ей место и показывать ли всегда или только после TTL. Смысл она приобретёт вместе с персистом.

Из пометки следует и второе требование: увидев возраст, человек захочет обновить данные сам — он не знает, когда это случится само. Значит пометка не может быть просто надписью, ей нужна либо кнопка обновления рядом, либо сообщение о том, когда произойдёт следующая попытка. Иначе она сообщает о проблеме и не даёт с ней ничего сделать.

**Пауза после `429`** — отложена. Ждать стоит только когда сервер сам сказал ждать; для этого понадобится код ошибки и отдельное время последней попытки. При работающем кеше обычное пользование в лимит не упирается (см. справку о лимите).

**Ревалидация открытой страницы отложена.** Единственный триггер проверки — переключение недели. Обновление через `visibilitychange` вернётся, когда появится причина: переносы уже объявленных релизов редки.

### 6.5 Отмена запросов и гонки

**Решено 02.10.2026.** Две ситуации, где ответ приходит, когда он уже не нужен: быстрые переходы между тайтлами и набор в поиске. Без защиты поздний ответ по прошлому запросу перезаписывает данные текущего.

**Запрос обрывается, а не просто игнорируется.** `AbortController`, его `signal` уходит третьим аргументом в `graphqlRequest` — конфиг там уже принимается, менять helper не нужно. Причина выбрать обрыв, а не сверку на выходе: у AniList есть ограничение по частоте, а при таймауте в 10 секунд брошенный запрос ещё и держит соединение.

**Одной отмены мало — нужна проверка актуальности.** Отменённый запрос попадает в `catch`, выходит по `return`, но **`finally` выполняется и после `return`**. Без проверки он погасит загрузку уже другого, живого запроса. Поэтому и в `finally`, и в успешной ветке стоит вопрос «этот контроллер ещё текущий?», и только при утвердительном ответе трогается состояние.

Сравниваются сами объекты контроллеров, а не идентификаторы: так работает и повторное открытие того же тайтла.

**Отмена не должна попадать под задержку ввода.** В поиске обрыв вызывается в необёрнутом обработчике, а отложен только сам запрос. Если отменять внутри отложенной функции, обрыв опаздывает на 500 мс — дольше, чем идёт запрос, и отменять оказывается нечего. Замер 02.10.2026: выдача по стёртой строке висела на экране почти секунду.

**`ERR_CANCELED` отсекается первой строкой `catch`**, иначе каждый быстрый переход показывает экран ошибки.

#### Композабл `useAbortController`

Общий для стора карточки и поиска, отдаёт три функции: создать контроллер (обрывая прежний), проверить актуальность, сбросить.

| Что отменяет                            | Чем закрывается                                             |
| --------------------------------------- | ----------------------------------------------------------- |
| предыдущий запрос при новом             | создание контроллера обрывает прежний                       |
| запрос при уходе со страницы тайтла     | обрыв в наблюдателе маршрута, при `params.id === undefined` |
| запрос при коротком вводе в поиске      | обрыв в обработчике ввода                                   |
| запрос при уничтожении области эффектов | `onScopeDispose` внутри композабла                          |

Последняя строка — страховка, а не работающий механизм: **область эффектов setup-стора Pinia привязана к экземпляру Pinia, а не к компоненту.** Уход со страницы стор не уничтожает, `onScopeDispose` там сработает только при закрытии вкладки. `SearchAutocomplete` тоже живёт всё время, он внутри шапки. Поэтому обрыв в наблюдателе маршрута обязателен и отдельно — заменить его на `onScopeDispose` нельзя.

## 7. Работа со временем — правила

Это самое ошибкоопасное место проекта. Правила обязательны к соблюдению.

1. **`airingAt` от AniList — unix-секунды в UTC.** Это абсолютный момент времени, одинаковый для всех на планете.
2. **Хранить и передавать — в unix/UTC. Форматировать — в самый последний момент, в компоненте.** Никаких «уже отформатированных» дат в сторе.
3. **Группировка по дням выполняется в локальной зоне пользователя**, а не в UTC и не в JST. `dayjs.unix(airingAt).format('YYYY-MM-DD')` даёт локальную дату — это и есть ключ группы.
4. **Не склеивать и не парсить даты строками вручную.** Никаких `new Date('2026-07-30')` — такая строка парсится как UTC-полночь, а не локальная.
5. **Для арифметики использовать календарные единицы, не часы.** `dayjs().add(1, 'day')` учитывает переход на летнее время, `add(24, 'hour')` — нет.
6. **Границы недели** — через плагин `isoWeek` (неделя с понедельника). Обычный `startOf('week')` зависит от локали и в en-US даёт воскресенье.
7. **Один тикер на всё приложение.** Обратные отсчёты не заводят по `setInterval` на карточку. В композабле `useNow` один интервал (раз в 30 сек), обновляющий реактивный `now`; карточки вычисляют разницу от него. Интервал очищается при размонтировании.
8. **Таймзона пользователя** определяется как `Intl.DateTimeFormat().resolvedOptions().timeZone`. **Язык интерфейса** — отдельная сущность, из `navigator.language` или выбора пользователя. Одно не выводится из другого.
9. `dayjs.locale('ru' | 'en')` переключается синхронно с языком vue-i18n. **Не сделано:** локаль dayjs задана статически (`ru` в `main.ts`), переключателя языка в интерфейсе нет.

## 8. Нефункциональные требования

- **TypeScript strict.** Сборка (`vue-tsc -b`) проходит без ошибок. Никаких `any` в прикладном коде (исключение — `AxiosRequestConfig<any>` в `api/request.ts`).
- **Адаптивность:** 360px — 1920px. Брейкпоинты в коде: 1240 (неделя / день в расписании, `useIsWideLayout`), 700 (баннер популярного), 650 (две колонки строчных карточек расписания). Планировавшиеся 640 / 1024 / 1440 не используются.
- **Доступность:** навигация с клавиатуры по карточкам и фильтрам, `alt` у изображений, `aria-label` у иконочных кнопок, видимый фокус.
- **Ленивая загрузка изображений** (`loading="lazy"`), заглушка на время загрузки — цвет берётся из `coverImage.color`, который AniList отдаёт вместе с обложкой.
- **Тёмная и светлая темы** — переключатель, выбор сохраняется.
- **Локализация** ru / en, выбор сохраняется. **Частично:** переводы обоих языков есть, язык читается из `localStorage`, но переключателя в интерфейсе нет, и `lang` не обновляется. При смене языка обновлять `document.documentElement.lang` — от него зависят переносы слов и произношение в скринридерах. В `index.html` он задан статически (`ru`).
- **Заголовок вкладки меняется по экрану** — **не сделано**, сейчас везде «Tsugi». Берётся из `meta` маршрута, а на карточке дополняется названием тайтла, когда придут данные. Пока данных нет — нейтральное «Tsugi», иначе в истории браузера останется «undefined». На экранах ошибок заголовок возвращается к нейтральному: во вкладке не должно висеть имя тайтла, которого нет. Название берётся по локали тем же `getMediaTitle`, что и на странице.
- **В репозитории нет** закомментированного кода, `console.log` и отладочных стилей.

### 11.1 Тесты (Vitest + Vue Testing Library)

Первая цель — чистые функции: группировка расписания по дням, вычисление границ недели, форматирование обратного отсчёта, парсинг и валидация фильтров из URL. Это функции без DOM и без сети, тестировать их проще всего, а покрывают они самую ошибкоопасную логику.

Вторая цель — сторы Pinia (кеш, TTL) и пара компонентов.

Цель не в проценте покрытия, а в наличии осмысленных тестов.

**Обязательное условие для тестов на даты.** Плагины dayjs подключаются в `main.ts` (`dayjs.extend(isoWeek)` и др.). В тестовом запуске `main.ts` не выполняется, поэтому в конфиг Vitest нужен `setupFiles`, повторяющий те же `extend`. Без него `startOf('isoWeek')` молча вернёт неизменённую дату — dayjs не распознаёт неизвестную единицу и не выдаёт ошибку, так что тест упадёт с сообщением, уводящим в сторону от настоящей причины.

### 11.3 OAuth AniList

**Нужен только для записи.** Чтение списка в MVP уже решено ником без авторизации (5.5), так что OAuth добавляет ровно одну возможность: отмечать статус и прогресс так, чтобы это сохранялось в аккаунте AniList (мутация `SaveMediaListEntry`), а не только локально.

Стор личного списка уже спроектирован под слияние источников, поэтому OAuth добавляет третий слой, а не переписывает модель. `localStorage` и чтение по нику остаются режимами для незалогиненных.

Может остаться неcделанным навсегда — ценность фичи невелика по сравнению со сложностью (два режима интерфейса, обработка истёкшего токена, совпадение redirect URI между localhost и продакшеном).

**Бэкенд не нужен.** AniList поддерживает implicit grant: после редиректа токен приходит прямо во фрагменте URL, обменивать его на сервере не требуется. То есть авторизация реализуема в чистом SPA и не противоречит разделу 12.

Осознанный компромисс: implicit grant отдаёт долгоживущий токен (у AniList — год), который хранится на клиенте. Для пет-проекта приемлемо, для продакшена потребовался бы authorization code flow с серверной частью.

### 11.4 Сравнение списков

Экран `/compare?a=ник1&b=ник2`: что смотрели оба, что смотрел только один, расхождение оценок. Работает по публичным никам, без авторизации — демонстрируется за 20 секунд. Заодно оправдывает всю работу с состоянием в URL.

### 11.5 PWA — TODO, отложено

**Статус: отложено осознанно.** Решение не принято, потому что польза для этого проекта пока неочевидна. Вернуться к вопросу, когда появится один из поводов:

- захочется открывать расписание с телефона как приложение, с иконкой на домашнем экране;
- понадобится офлайн-доступ к расписанию;
- проект будет готов, и захочется добавить заметный пункт в README.

Что это даст технически: `vite-plugin-pwa` генерирует манифест, иконки и service worker. Приложение устанавливается на телефон, расписание доступно офлайн из кеша. Push-уведомления «серия вышла» требуют серверной части и в рамках фронтенд-проекта не делаются.
